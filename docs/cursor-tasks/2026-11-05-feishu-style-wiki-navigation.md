## 2. 产品目标与交付范围

### 2.1 必须完成的用户流程

作者打开颗秒文档 → 新建/打开文档 → 设置标题级别 → 输入文字并插入图片 → 自动出现本篇目录 → 在阅读模式预览 → 将文档组织到知识库/文件夹 → 设置网页分享 → 复制文档或章节链接 → 访客在电脑、手机或微信内打开并阅读 → 作者可继续修改、管理分享或撤销分享。

这是一套真实编辑、保存、组织、阅读、分享流程。不能用静态图片、假数据列表、PDF 展示页或只能作者本人打开的编辑链接代替。

### 2.2 必做与可选边界

| 优先级 | 范围 |
| --- | --- |
| 本次必做 | 本篇自动目录、稳定锚点、滚动高亮、图文阅读、阅读/编辑模式、知识库树、面包屑、基本标签与搜索、单文档分享、知识库分享、权限隔离、桌面/手机适配、持久化与上线 |
| 兼容性必做 | 既有私有文档/本地草稿、登录、保存、上传、导入导出与打印入口、旧路由、现有编号/页眉页脚/公式等数据不被本次改动破坏 |
| 可选增强 | 可配置水印、侧栏拖拽调宽、阅读进度、额外主题、搜索结果命中章节 |
| 本次不要求新增 | 多人实时协同光标、全新商城/分销、全新办公套件、重写 MathCode、强制拆服务、重建统一账号、重做完整 Word 排版引擎 |

可选增强不应延误必做范围。不得将知识库树或访客分享归到“以后再做”，然后把整项任务标为完成。

### 2.3 三种结构各司其职

| 名称 | 数据对象 | 用户点击后的行为 |
| --- | --- | --- |
| 知识库 | 空间、文件夹、文档 | 展开目录或切换不同文档 |
| 本篇目录 | 当前正文中的真实标题块 | 在当前文档内跳转到章节 |
| 标签 | 文档的主题关键词 | 筛选可访问的相关文档 |

左侧建议采用“知识库 / 本篇目录”两个明确入口，或有清楚标题的上下分区。基础模式采用双栏：左侧导航、右侧正文。宽屏可扩展，但不能把两个导航都挤在固定窄列里。

单文档分享默认展示本篇目录；知识库阅读提供文档树和当前文档大纲。标签不充当面包屑或标题目录，也不改变文档的实际父子关系。

## 3. 本篇目录、标题与稳定锚点

### 3.1 自动生成真实大纲

- 目录从当前持久化内容中的语义标题生成；不能要求作者额外维护一份目录。
- 支持现有标题 1–6，至少明确展示 H1–H3，可配置展示的最大层级；普通粗体段落不自动当作标题。
- 新增、改名、改级别、移动、删除标题时，大纲与正文及时同步；目录本身不触发多余的内容保存循环。
- 正确处理跨级标题、重名标题、中文标点、emoji、超长标题、空标题，以及无标题文档。
- 大纲按层级缩进并可折叠；长标题可省略，但应有键盘/触屏可用的完整标题查看方式。
- 无标题时提供简短提示“设置标题后，这里会自动生成目录”，并保留现有内容。
- 文档标题与正文内部标题分别处理；不要把标题字段重复插入正文或批量改写历史标题级别。

### 3.2 持久化标题身份

选用稳定、唯一的标题块 ID；具体字段名沿用现有架构。要求：

1. 在内容模型、Tiptap 扩展、JSON 清洗、序列化、服务端读写、只读渲染、HTML 转换中贯通。
2. 标题重命名、移动，在其前面插入章节，均不改变原标题身份。
3. 同名标题有不同身份；复制章节时生成新 ID，撤销/重做不会制造重复 ID。
4. 旧文档缺少 ID 时采用幂等兼容策略；不在每次渲染随机生成，更不能因查看页面就不断写库。
5. 如首次兼容需要补齐持久化 ID，应在有权限的保存/受控迁移中处理；客户端和服务端得到相同的锚点。
6. 章节链接使用目标页面的正确路径和锚点。访客分享不能复制成私人编辑路径。
7. 已删除章节的链接要给出“章节已调整或删除”的合理降级，不跳到另一段同名内容。
8. 不以标题文字 slug、当前数组下标或目录序号作为唯一身份。

### 3.3 点击定位与滚动高亮

- 点击目录滚动到对应标题，预留固定顶栏与文档工具栏的遮挡高度。
- 正文手动滚动时同步高亮当前章节；短章节、最后一节、图片间大空白均有明确的判定。
- 用实际滚动容器作为观察根；组件卸载时清理观察器、事件和定时器。
- 左栏可以独立滚动；高亮自动跟随不反复抢夺用户手动滚动目录的控制权。
- 支持复制章节链接、直接打开带 hash 的 URL、刷新、前进/后退和跨文档返回。
- 不在每个滚动像素都新增浏览器历史；区分用户点击导航与被动滚动。
- 图片迟加载、字体加载、侧栏展开收起后，目标章节仍可定位正确。需要二次修正时限定次数，避免反复抢滚动。
- 遵从减少动画偏好；有键盘焦点与可理解的当前项状态。

## 4. 编辑、保存与图文阅读

### 4.1 作者编辑体验

- 复用现有 Tiptap 编辑器、工具栏、自动保存和上传服务，清楚提供正文/标题 1–6选择。
- 保留粗体、列表、多级编号、表格、页眉页脚、打印与已有其他节点。超链接如需新增，应补齐链接标记、允许协议校验、清洗及往返保存，不能假定当前已经具备。
- 支持上传图片及粘贴图片；编辑过程中可调整位置、删除，上传失败有重试和错误提示。
- 未登录本地草稿继续可用；发布或云端分享前，提示登录并将草稿完整保存到本人云端文档。
- 不能把浏览器 localStorage 中的草稿 URL 当作可分享网页。
- 清楚显示“保存中 / 已保存 / 保存失败 / 有未保存更改”。分享前必须确认所需内容保存成功，失败时保留本地编辑内容。
- 处理自动保存请求乱序，避免旧请求覆盖新内容。沿用或补齐版本/更新时间校验；多标签页冲突应提示用户。
- 阅读和编辑切换时不丢失未保存内容；切换文档时刷新大纲、正文和权限，不出现上篇残留。
- 上传、保存、分享等按钮有真正后端处理，不能只弹成功消息。

### 4.2 图文阅读

- 连续正文清晰可读；段落、标题、列表、表格和图片不被强制切成宣传卡片。
- 图片保留比例，限制最大宽度；细长截图不强制拉伸铺满屏幕。
- 点击图片可放大，支持关闭、必要的缩放/移动；移动端触摸可操作，键盘用户可退出。
- 对图片保存必要尺寸或比例信息，延迟加载时预留空间，减少正文跳动。
- 使用可长期访问的正式资源引用，不保存临时 blob URL、本机文件路径或作者会话专用临时地址。
- 图片加载失败提供占位与重试，不遮住后续正文。
- 正式图片和附件沿用公共存储配置与权限能力；不能另建一套硬编码 OSS、密钥或上传配置。
- 从其他文档粘贴 HTML 时清洗危险内容，并保护合法标题、列表、表格和图片结构。不能把未审核 HTML 直接注入页面。
- 如果最新版已有数学公式、代码块或其他自定义块，阅读器和保存链路须支持；未实现的历史数学任务如实列明，不把未知节点静默删除。

### 4.3 导入、导出与打印边界

- 本次新加的标题 ID 和内容属性必须经过导入/保存/读取/HTML 渲染往返校验。
- 针对已有导入入口，保留现有能识别的语义标题层级，修复图片、表格等结构在导入链路中被静默丢失的问题。无法转换的元素明确提示；仅字号或粗体不能冒充语义标题。
- HTML 导出保留语义标题、稳定锚点及可用的图片引用；若新增独立 HTML 目录，复用相同的大纲生成逻辑。
- 私密图片导出要区分在线链接与离线副本；不能把短期签名地址描述成永久离线文件。
- 保留 Word/TXT 导出和打印入口。现有 Word 图片占位等历史限制要清楚披露；本次不承诺 DOCX 全格式无损转换。
- 导航和编辑控件不进入打印正文。打印页眉、页脚和页码按原设计保留，阅读侧栏样式不能污染打印分页。

## 5. 知识库、文件夹、标签与搜索

### 5.1 最小可用知识库

实现真实持久化的空间/知识库、文件夹与文档组织能力：

- 创建、重命名知识库和文件夹；新建/加入文档；调整文档顺序与归属；展开/收起多级树。
- 文档的正式身份与父目录位置分离；移动和重命名不导致文档 URL 失效。
- 父子关系防环；不能把父文件夹放入子文件夹。排序更新应避免并发导致重复或丢失。
- 提供触屏可用的“移动到/排序”操作。拖拽可作为增强，不能是手机上唯一的管理方式。
- 文件夹删除需明确处理子内容；优先移入回收站或移回根目录，不静默永久删除整棵树。
- 旧文档仍能从“我的文档”找到，可放入默认个人空间或“未分类”；迁移后不丢文档、不重复创建。
- 基础模型允许每个节点一个正式父级；若已有快捷方式/引用能力则保留，不因本次树设计删除它。
- 面包屑显示有权限查看的当前位置；可以逐级返回。
- 空状态、加载、失败、无权限和删除后的降级可用，不留死按钮。
- 基本个人空间和只读分享为本次目标，成员协作权限复用已有机制，不引入第二套账号系统。

### 5.2 标签

- 支持新建/选择/移除文档标签，同篇文档可以有多个标签。
- 统一清理空白与重复，支持中文；标签标识与展示名分离，改名不破坏关联。
- 提供标签筛选，并明确筛选范围。文档树的展开状态与标签筛选不混为一件事。
- 访客只能看到授权公开范围内的标签、结果及计数，不泄露私有文档信息。
- 本次采用简单多标签即可；不把“所有标签系统都必须无层级”写成实现限制。

### 5.3 搜索

- 登录作者可在其有权访问的文档范围搜索标题、正文纯文本及标签。
- 知识库访客搜索只覆盖当前允许访问的发布集合；单文档访客可查找本文。
- 结果包含标题与适度摘要，并能打开正确文档；关键词高亮不破坏 HTML 清洗。
- 不依赖外部搜索服务作为首发前提，可按当前 SQLite/Prisma 条件做有界的分页检索。
- 查询、结果摘要、数量、预取和缓存都遵守同一权限规则。

## 6. 阅读布局、品牌与移动端

### 6.1 桌面

- 使用清楚的顶部面包屑/文档信息，左侧目录，右侧正文。
- 侧栏参考宽度约 260–340px，根据现有整体导航调整；正文保留合理阅读宽度并支持较宽图片和表格。
- 左栏固定或粘性显示，长目录可独立滚动；正文不得被侧栏、固定顶栏或底部浮层遮挡。
- 可整体收起/展开侧栏；展开状态可按用户偏好保存。
- 正文用深色高对比文字，层级、字号、留白清楚；当前章节高亮，不能只靠颜色提示状态。
- 展示真实更新时间；作者/空间名称仅显示有权披露的内容。
- 文案和页面 metadata 统一使用“颗秒文档”，保留旧路径与现有入口兼容。
- 复用颗秒现有视觉组件和品牌；不带飞书 Logo、第三方组织名或参考页的真实案例内容。

### 6.2 手机与微信内置浏览器

- 小屏优先正文，以明确的“目录”按钮打开抽屉；提供知识库与本篇目录的清楚切换。
- 选择章节后关闭抽屉并滚动到目标。关闭后恢复页面滚动，处理遮罩、返回、焦点及安全区域。
- 关键按钮不依赖 hover；图片查看、移动文档、复制链接均可点按。
- 320px、375px、390px 等窄屏无整体横向溢出；宽表格/代码块在自身容器内横向滚动。
- 处理动态视口、软键盘和顶栏高度，避免手机底部按钮被挡住。
- 公开阅读不依赖第三方 Cookie、不要求弹窗登录；分享链接使用直接可打开的同源路径。
- 复制 API 不可用时提供可选中的完整链接及明确提示，不假报复制成功。
- 验证 iPhone Safari、Android 浏览器、微信内置浏览器。只有自动化 WebKit 结果时，明确标为“WebKit 自动化验证”，不能标为 iPhone/微信实机通过。

## 7. 网页分享与权限：必须完整实现

### 7.1 分享方式

至少具备：

1. 私有文档：默认仅现有权限允许的用户可访问。
2. 单文档链接分享：作者显式开启后，访客不用注册或安装客户端即可只读查看该文档、图片和本篇目录。
3. 知识库链接分享：作者显式选择可分享文档集合，访客可在授权文档树中切换；未经选择的私有内容不展示。
4. 随时撤销/重新生成分享；支持可选有效期。口令不是默认必填项，不为普通公开阅读强加复杂步骤。
5. 分享面板清楚显示访问范围、是否会随作者保存更新、失效时间及复制链接入口。

当前代码没有发布快照。优先采取架构内最简单可靠的方式，例如“已保存内容实时分享”，并在界面明确“保存后会更新分享页面”。如果最新版已有草稿/发布版本，则严格沿用版本边界，未发布草稿不能混入访客视图。

分享知识库时，新增文档默认仍私有，不因归入目录而自动公开。改变父级、复制文档、恢复回收站均不能无提示扩大分享范围。

### 7.2 后端授权

- 维持原有私人编辑页面和 /api/docs 写接口的用户隔离。
- 新增独立的受控只读读取入口；根据真实用户权限或有效分享凭证判定可读范围。
- 分享凭证不可预测，采用项目适合的安全随机生成与存储方案；令牌不用作编辑权限。
- 文档详情、树节点、标题、标签、搜索摘要、面包屑、附件和预取接口全部校验范围。
- 只分享 A 文档不能得到同空间 B 的标题、文档 ID、正文或资源地址；必要时用安全的虚拟分享根节点。
- 不通过前端隐藏节点替代服务器授权；猜测 ID、替换路径参数或直接请求 API 不能绕过限制。
- 私有图片或附件要受实际存储/读取权限保护。核对现有上传的公开性，不能只隐藏网页就宣称图片私有。
- 私密文档资源的授权改造限定在文档资源范围，保持公共上传服务与其他产品现有图片链接兼容；不批量删除旧资源、统一收紧公共资源 ACL 或全局改写图片 URL。旧资源若已公开流通，如实披露既有副本无法收回，并采用兼容的受控资源方案。
- 分享撤销、过期、文档删除或权限收紧后，新请求按新权限拒绝；缓存同步失效，分享响应不能被错误跨用户复用。
- 如资源采用短期签名，明确最长可继续访问窗口并尽量缩短；不要承诺已下载/截图的副本能被收回。
- 对无效或撤销链接显示可理解的页面，不透露文档私有详情。
- HTML 清洗、链接协议、图片地址和上传校验遵守现有安全边界；不接入任意 URL 抓取器，不制造服务端任意地址请求能力。
- 普通用户不能借移动节点、重命名空间或分享集合操作越权编辑他人内容。

### 7.3 可选水印

可增加管理员/作者可配置的文字水印，默认关闭，不阻塞核心上线：

- 可设置品牌文字、透明度、间距，预览可见。
- 不默认显示真实手机号、邮箱、IP 或其他个人信息；访客标识如有需要只采用适当的匿名编号。
- 水印不拦截点击，不压住目录或图片；打印是否包含由明确设置决定。
- 不宣称可防截图、防录屏或彻底防复制。

## 8. 数据模型、迁移与实现纪律

### 8.1 按当前架构增量扩展

可增加或扩展空间、目录节点、标签关联、分享记录等模型，命名由现有代码风格决定。至少考虑：

- 分享设置与访客读取权限。
